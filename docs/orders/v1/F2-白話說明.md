# F2 白話說明：讓前端看得到「下了哪些單、成功了沒」

> 這份是 [F2 工單](F2-fubon-order-query.md) 的白話導讀。屬**富邦串接系列**，接在 [F1](F1-fubon-account-balance.md)（帳戶餘額）之後。

---

## 一句話

**這張票 = 後端跟富邦要今天的委託清單，把「狀態碼 10、50、90」這種數字翻成人看得懂的「委託成功、完全成交、失敗」，再給前端。**

---

## 現況與痛點

前端現在對委託一無所知。帳戶裡有哪些單、成交了沒、失敗的話為什麼失敗，全部問不到。

富邦有現成的 `get_order_results` 可以查今日委託，但它回的狀態是**一個整數**。前端拿到 `10` 是看不懂的，這種翻譯要在後端做完，不能丟給前端去背。

---

## 這張票做的事（白話）

開一支 `GET /account/orders`，回今天的委託清單，每筆長這樣：

| 回傳欄位 | 白話 |
|---|---|
| `orderNo` | 委託書號 |
| `stockNo` / `buySell` | 哪一檔、買還是賣 |
| `price` / `quantity` | 委託價、委託股數 |
| `filledQty` / `filledMoney` | 成交幾股、成交多少錢 |
| `status` | **成功與否**（見下表） |
| `rawStatus` | 富邦原始的數字碼 |
| `errorMessage` | 這筆單失敗的原因 |

`status` 的翻譯：

| 我們回的值 | 富邦狀態碼 | 意思 |
|---|---|---|
| `pending` | 0 / 4 / 8 / 9 | 還在處理，結果未定 |
| `accepted` | 10 | 委託成功，還沒成交 |
| `filled` | 50 | 完全成交 |
| `partially_filled_cancelled` | 40 | 成交一部分，剩下取消了 |
| `cancelled` | 30 | 沒成交就被刪單 |
| `failed` | 90 / 19 / 29 / 39 | 失敗 |

**表上沒有的碼一律回 `unknown`，不准猜。** 富邦哪天加了新狀態碼，我們寧可顯示「不明」也不要把它誤判成「成功」——後者會讓使用者以為單子下出去了。`rawStatus` 保留原始數字，就是為了出事時查得到真相。

---

## 兩種「錯誤訊息」要分清楚

這是最容易寫錯的地方：

- **連線層的錯誤**（登入失敗、券商掛了）→ **不給前端看**，只寫進伺服器 log。那種訊息會洩漏券商內部細節。
- **單筆委託的錯誤**（例如「餘額不足」）→ **要給前端看**。那是使用者自己那張單的結果，藏起來反而沒用。

---

## 這張票的邊界

| 不做 | 原因 |
|---|---|
| 下單 / 改單 / 刪單 | 另外的票 |
| 查歷史成交、查委託歷程 | 等真的開始送單、確定前端要怎麼呈現再說 |
| 即時推播委託回報 | 這張票是「使用者開頁面時查一次」 |
| 把委託存進我們的資料庫 | 現在是即時透傳。存 DB 的時機是「開始下單之後」，見下 |
| 期貨 | 只做證券 |

---

## 順便講清楚：以後績效怎麼算（這張票不做）

因為討論到「主管帶交易員、要看各人績效」，先把界線定下來，免得做下單票時重想一次：

**富邦已經幫我們算好很多東西**——成交價、持倉、已實現損益、未實現損益，券商都查得到。所以：

| 資料 | 放哪 | 為什麼 |
|---|---|---|
| 這張單是哪個 intent 觸發的、是誰送的 | **我們自己的 DB** | 只有我們知道，券商不可能回答 |
| 成交價、持倉、賺賠 | **每次查富邦** | 券商是唯一真相來源 |

⚠️ **千萬不要自己維護一份持倉表。** 使用者隨時可能打開富邦 App 自己賣掉，我們的表立刻就錯，然後就得開始寫對帳程式——等於把券商的帳本重建一遍。

而「哪張單是誰送的」這件事，**現在還記不了**，因為階段一根本不下單，沒有委託書號可記。它的落點是下單票，現在建就是一張空表。

**還有一件事要跟富邦問清楚**：文件裡的「最多 30 把」是 **API Key 的上限**，不是 30 個子帳號，而且用 API Key 登入還是要帶主帳號的憑證。如果 30 把 key 都綁在同一個帳號底下，富邦回報裡的帳號欄位會**完全一樣**，券商端根本分不出是哪個交易員下的單——那績效歸屬就只能靠我們自己記。這個前提沒確認之前，不要照「每個交易員一組憑證」去設計。

---

## 做完之後

前端可以顯示今天的委託與結果；等下單功能開工時，「送出去的單怎麼查結果」這條路已經是通的，那張票只要專心處理送單就好。
