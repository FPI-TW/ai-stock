# F3 白話說明：讓前端看得到「我手上有哪些股票」

> 這份是 [F3 工單](F3-fubon-position-query.md) 的白話導讀。屬**富邦串接系列**，沿用 [F1](F1-fubon-account-balance.md)（帳戶餘額）的登入，與 [F2](F2-fubon-order-query.md)（今日委託）可平行做。

---

## 一句話

**這張票 = 後端跟富邦要庫存清單，讓前端顯示「我有哪些股票、幾股、可以賣幾股」。**

---

## ⚠️ 先講清楚：這張票**看不到賺賠**

原本想的是「持倉 + 現在賺多少賠多少」。實際打了測試帳號之後，這件事**階段一做不到**：

- 富邦查未實現損益的那支 API，測試環境**直接回失敗**：「證券報表/表單定義資料不存在」。
- 而庫存這支 API 回的資料裡，**沒有成本價、沒有市值**，只有股數和今天買賣的價金。

沒有成本價就算不出賺賠，硬湊只會湊出錯的數字（今天的買入價金不等於持倉成本，昨天以前買的部位完全不在裡面）。

**所以這張票交付的是「我有哪些股票」，不是「我賺了多少」。** 排期和 demo 預期請照這個範圍設定。
賺賠等接上正式帳號、確認那張報表存在之後再開票。

---

## 那還做它幹嘛？

**因為停損停利需要它。**

我們已經定案停損停利要自己盯價、兩個價位都必填。使用者要對手上的股票設停損，現在只能**自己打股票代號和股數**——打錯了系統也不知道，因為系統根本不知道你有什麼。

有了持倉清單，建單就可以「從我手上的股票裡挑一檔」，數量上限也有依據。

其次才是 demo：盯盤工具秀不出使用者手上有什麼，說服力差很多。

---

## 這張票做的事（白話）

開一支 `GET /account/positions`，回庫存清單，每筆長這樣：

| 回傳欄位 | 白話 |
|---|---|
| `stockNo` | 股票代號（可能有英文，像 `00720B`）|
| `orderType` | **現股 / 融資 / 融券** |
| `todayQty` | 目前持有幾股 |
| `tradableQty` | **可以賣幾股**（設停損時的數量上限看這個）|
| `lastdayQty` | 昨天有幾股 |
| `buyQty` / `sellQty` 那幾組 | 今天買了賣了多少、成交價金多少 |
| `odd` | 零股的同一組數字 |

單位是**股**不是張，`500000` 是 500 張。後端不幫忙換算，前端要顯示張數自己除。

---

## 實際打過測試帳號才發現的三個坑

這三個是本票最容易寫錯的地方，寫進工單就是為了讓施工的人不用再踩一次：

### ① 同一檔股票會出現好幾筆

實打結果裡 **2330 出現了三次**：現股一筆、融資一筆、融券一筆。

所以「一檔一筆」是錯的。**不能拿股票代號當唯一的 key 去合併或去重**，那樣會直接把資料蓋掉——使用者的融資部位就這樣消失了。真正的唯一鍵是「股票代號 + 現股/融資/融券」。

而且現股跟融券的部位性質完全相反，翻譯錯了會讓使用者對著融券部位設出方向反了的停損。所以富邦給的值如果不在我們的對照表裡，**一律回 `unknown`，不准猜成現股**。

### ② 持有股數可能是**負的**

實打的 2412 是 `todayQty: -1000`（今天先賣掉、還沒買回來）。這是真實的部位，**不是錯誤、不能濾掉、不能取絕對值**。

### ③ 有一堆「全是零」的空殼

實打 9 筆裡有 3 筆所有數字都是 0（那檔今天沒部位也沒動作）。這是富邦資料的形狀，不是 bug。**後端把全零的濾掉**再給前端，不然畫面上三分之一是雜訊。

但要注意，濾的是「全零」，**不是「股數小於等於零」**——不然上面那筆負數的真實部位就被誤殺了。

## 這張票的邊界

| 不做 | 原因 |
|---|---|
| 未實現損益 | 測試環境那支 API 直接失敗，做了也測不到、demo 不出來 |
| 已實現損益 | 沒有委託單號，對不回任何東西，就是一張看不懂來源的數字表 |
| 自己算成本、市值、手續費、稅、報酬率 | 富邦沒給成本價，自己湊的一定是錯的 |
| 把整股和零股加起來 | 兩者語意不同，合併會出錯。零股原樣給，前端自己決定怎麼呈現 |
| 把持倉存進我們的資料庫 | 見下 |
| 下單 / 改單 / 刪單 | 另外的票 |
| 期貨 | 只做證券 |

---

## ⚠️ 千萬不要自己維護一份持倉表

這是產品紅線，不是這張票偷懶。

使用者隨時可能打開富邦 App 自己買賣，我們存的那份快照**立刻就錯了**。錯了之後就得開始寫對帳程式，等於把券商的帳本整個重建一遍——而且永遠對不完。

**持倉每次都去問富邦。券商是唯一的真相來源。**

---

## ❌ 順帶：不做「哪些股票是誰的」

子帳號系統已於 2026-08-28 整套取消。一個帳號底下只有一個庫存池、股票是可替代的，**「這 500 張是 A 的」這件事根本不存在**，富邦回的持倉也全是整個帳號的合計。要分人就一人一個證券帳戶、一套部署。

---

## 做完之後

前端可以顯示帳戶持有哪些股票與股數；停損停利建單時，使用者可以從自己的持倉裡挑，不必手打代號。
賺賠的數字等接上正式帳號、確認報表存在之後另開票。
