# L2 白話說明：平台守門 / 防護（含緊急停止鈕）

> 這份是 [L2 工單](L2-platform-guard.md) 的白話導讀，給非工程背景的人快速理解「L2 在做什麼、對齊 spec 哪些範圍」。技術細節以工單本體為準。

---

## 一句話

**L2 = 平台的「保全與防呆層」，外加一顆出事時能自己按的緊急停止鈕。** 如果 L1 是「裝大門發鑰匙」，L2 就是「裝監視器、防呆、保全規則 + 緊急停止鈕」。

---

## 為什麼需要 L2

L1 把身分做好了，但光能登入還不夠安全。還要防止有人亂搞、防止手滑、出事能查、能止血。L2 把 5 個「**跟單一功能無關、但保護整個平台**」的東西收在一起。

---

## L2 做的 5 件事（白話）

**1. 稽核紀錄（誰在何時做了什麼）**
幫每個重要動作留紀錄：誰建提醒、誰取消、誰停用帳號、誰按了緊急停止鈕……
> 像大樓門禁刷卡紀錄。出事時能回查「發生什麼、誰做的」。
（L1 先用簡易版佔位，L2 換成正式紀錄表，並把 L1 那些佔位處接上真的。）

**2. 防止「按兩次變兩筆」（冪等）**
網路卡頓時使用者常多按幾次送出，沒防護就會建出重複提醒。
> L2 讓每次送出帶一個「序號」，同序號送幾次都只算一筆。像超商條碼，重複刷只算一次。

**3. 限流（防止狂打）**
同一人/同一台電腦短時間塞爆系統就擋下，回「太頻繁，請稍候」。
> 防止有人或壞掉的程式一秒打幾百次拖垮伺服器。L1 已做好「登入防爆破」引擎，L2 把它擴大到所有會「動到資料」的操作。

**4. 建立數量上限**
一個人最多同時盯 200 筆、同一檔股票最多 20 筆，超過就擋。
> 防止手滑或惡意建幾萬筆灌爆系統。數字先寫在設定檔（之後 P5 才讓管理員能線上調）。

**5. 🔴 緊急停止鈕（最小版，止血用）**
管理員一鍵讓系統**停止發提醒**。
> 按下去後：系統還是繼續抓股價（畫面看得到行情），但不再判定到價、不發任何通知。要 2FA、要填原因、會留紀錄、幾秒生效。
> 重要限制：這是「**止血不是重播**」——停掉期間錯過的到價不會補發。

---

## 對齊 domain-spec 的範圍

L2 把 spec 裡**散在 5 個章節、但性質都是「跨業務平台防護」**的條文收成一張。逐項對照：

| L2 做的事 | 對齊 spec 出處 |
|---|---|
| 稽核紀錄（15 個最低事件 + 5 欄位） | **§17 Audit Log** lines 1040–1070 |
| 冪等（Create/Cancel/CancelGroup + 缺 key 拒絕 / 衝突 409 / 存 24h） | **§16** lines 997–1012 |
| Request/Correlation id 貫穿 | **§16** lines 902–909 |
| 建立上限（user 200 / 單標的 20、不寫死） | **§15** lines 850–861 |
| 限流擴到全 mutating endpoint | **§13** lines 746–753 + **§16** `RATE_LIMITED` line 943 |
| 錯誤碼正典 + HTTP status mapping | **§16** lines 926–943、966–974 |
| 緊急停止鈕（全系統停止觸發、quote 仍抓不觸發、寫 audit） | **§18** lines 1086–1098 |

**一句話**：L2 = domain-spec **§13 / §15 / §16 / §17 / §18** 裡「平台級防護」條文的集合，按「跨業務共用守門」這個內聚軸收成一張。

---

## ⚠️ 一個要知情的落差：緊急停止鈕只做「最小版」

spec §18 要求 kill switch **「必須分層控制」，共 5 層**：

1. 全系統停止觸發 ← **L2 只做這層**
2. 特定 symbol 停止觸發 ← P5
3. 停止 Telegram 發送 ← P5
4. 停止所有外部通知但保留站內 ← P5
5. 停止 corporate action adjustment 套用 ← P5

**白話後果**：上線時只有「全部喊停」一顆鈕，**不能只停某一檔、只停 Telegram、或只停除息調整**——要嘛全停、要嘛全開。這是經確認的刻意縮小（上線先有止血閥即可），完整 5 層留 **P5**。

---

## L2 的邊界（不做什麼、交給誰）

| 不做 | 交給 |
|---|---|
| RateLimiter 引擎本體（L2 沿用、不重建） | **L1** 已建 |
| 限額讓 admin 線上調（L2 先用設定檔預設） | **P5** |
| kill switch 其餘 4 層分層控制 | **P5** |
| 資料保留/清理政策（L2 只建紀錄表） | **P6** |
| 通知交付保證 outbox（L2 只打通 correlation id） | **P2** |

---

## 兩個「不在 L2、但有著落」的項目

- **去重**（禁止同一交易日建完全相同 intent）：**V0.5 已交付**，不是漏做。
- **「避免通用 `deleted_at`」原則**：放在 **P6** 統一處理。

---

## 做完 L2 之後

平台變得「**有紀錄、防呆、防爆、有上限、能緊急喊停**」。加上 L1 的身分，就只差 L3（把網站本身鎖緊 + 架上正式機器）就能上線了。
