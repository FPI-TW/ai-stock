# L3 白話說明：安全與部署硬化

> 這份是 [L3 工單](L3-security-deployment-hardening.md) 的白話導讀。技術細節以工單本體為準。

---

## 一句話

**L3 = 把網站本身鎖緊、架上正式機器、確保上得去也救得回。** 這是「防護」的部署面與安全面，是上線最後一哩。

---

## 為什麼需要 L3

L1（身分）、L2（守門）都做好了，但程式還跑在開發環境、網站本身的安全設定還沒鎖緊。L3 負責把它變成「能對外、扛得住、出事能還原」的正式服務。

---

## L3 做的事（白話）

**1. 把網站表面鎖緊**
防止常見的網路攻擊：偽造請求（CSRF）、跨網站亂接（CORS）、cookie 被偷、瀏覽器被騙。設定一整套安全規則，只允許自己的前端來存取。

**2. 密碼規則（簡單版）**
至少 8 個字，不強制大小寫數字符號，也不做外洩密碼檢查（之後版本再加強）。

**3. 機密不外洩**
密碼、金鑰、資料庫連線這些祕密全部放在環境設定裡，不寫進程式碼、不進版控；正式環境少了關鍵祕密就直接拒絕啟動（避免裸奔上線）；紀錄檔不印出任何祕密或個資。

**4. 架到正式機器**
單機伺服器 + 資料庫（不搞複雜的雲端叢集），上 HTTPS 加密，開發用的測試後門在正式環境關掉。

**5. 備份與災難復原**
每天自動備份資料庫、能還原到任意時間點；**上線前先實際演練一次「把資料救回來」**，確認真的救得回，不是紙上談兵。

**6. 上線前最後測試**
把「收到邀請 → 登入 → 建提醒 → 收站內通知 → 登出」整條流程跑一次自動測試，加一份上線冒煙檢查清單。

---

## 對齊 domain-spec 的範圍

| L3 做的事 | 對齊 spec 出處 |
|---|---|
| CSRF / CORS / cookie / SameSite / Origin 檢查 | **§13** lines 730–738 |
| 密碼規則 MVP（≥8 字元） | **§13** lines 739–744 |
| Process 邊界（web / evaluator / notification / jobs 不互相拖垮） | **§16** lines 885–900 |
| 備份 / PITR / RPO 24h / RTO 4h / 還原演練 | **§22** lines 1151–1158 |
| 認證流程 E2E / 上線冒煙測試 | **§23** lines 1160–1194 |

> 註：機密進 env、單機部署、HTTPS、OpenAPI 產出屬「工程/架構交付物與安全慣例」，domain-spec 未逐條規範（部分對齊全域安全守則與舊 BE-V1-17/19）。

**一句話**：L3 切自 spec **§13（安全設定）+ §16（process 邊界）+ §22（備份/DR）+ §23（測試）**，再加上必要的部署與機密管理慣例。

---

## L3 的邊界

| 不做 | 交給 |
|---|---|
| 各業務功能測試 | 各 WO 自帶 |
| 完整 SLO 量測與告警 | **P6 / P5** |
| 多機水平擴展 / sharding | post-V1 |
| WAF / DDoS 等基礎設施防護 | infra（列風險，非後端工單） |

---

## 做完 L3 之後

**L1 + L2 + L3 三包到齊 → 可以上線。** 真人能安全登入、各看各的、平台有防護與止血鈕、網站鎖緊、架在正式機器、出事救得回。其餘 P1–P6 上線後迭代。
