# P2 白話說明：通知交付保證（Outbox）

> 這份是 [P2 工單](P2-outbox-notification-delivery.md) 的白話導讀。屬**上線後**迭代。

---

## 一句話

**P2 = 把「偶爾可能漏通知」修成「保證送達、會重試、有紀錄」。**

---

## 現況與缺口

V0.5 觸發後是「**直接寫通知 + 盡力送 Telegram**」，沒有保證、沒有重試。上線初期可接受，但要把可靠度拉滿就靠 P2。

---

## P2 做的事（白話）

**1. 先記帳再送（Outbox 信箱機制）**
觸發到價時，在同一個資料庫動作裡「先把要發的通知記進一個待辦信箱」。就算當下送信失敗，信箱裡的待辦還在，之後一定會被處理到。
> 像寄掛號：先在櫃台登記，沒寄成功還能補寄，不會憑空消失。

**2. 專門的送信員 + 不重複**
背景有送信員不斷從信箱撈待辦來送，可以多人同時送但保證**同一則不會送兩次**。

**3. 重試規則**
- Telegram 暫時性失敗（塞車、逾時）：自動重試 3 次、間隔越拉越長。
- Telegram 永久失敗（被封鎖、找不到對話）：標記這個綁定壞了、之後不再送 Telegram，但**站內通知照留**，並在畫面提示綁定異常。

**4. 每則通知留快照**
把當下發出去的標題、內容存一份。之後就算改了通知模板，回頭看歷史通知還是當時的樣子。

## 對齊 domain-spec 的範圍

| P2 做的事 | 對齊 spec 出處 |
|---|---|
| Transactional outbox（先記帳再送、at-least-once、claim/lock） | **§16** lines 1014–1038 |
| NotificationDelivery 狀態機（pending/sent/failed/skipped） | **§12** lines 626–635 |
| 重試 / 永久失敗 / skip 規則 | **§12** lines 637–645 |
| Rendered 通知快照（template 改版不影響歷史） | **§12** lines 613–622 |

**一句話**：P2 切自 spec **§16（transactional outbox）+ §12（通知失敗規則與 delivery 狀態機）**。

---

## P2 的邊界

| 不做 | 交給 |
|---|---|
| Telegram 綁定流程 | **P3**（P2 只查綁定狀態決定送/不送） |
| 通知偏好設定 | **P3** |
| 改通知文案 / 類型 | 沿用既有 + P1/P4 新增者 |

---

## 做完 P2 之後

通知從「偶爾可能漏」變成「保證送達、會重試、可追查」。
