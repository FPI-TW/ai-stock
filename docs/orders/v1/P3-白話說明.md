# P3 白話說明：Telegram 綁定 + 通知設定

> 這份是 [P3 工單](P3-telegram-binding-notification-settings.md) 的白話導讀。屬**上線後**迭代。

---

## 一句話

**P3 = 讓使用者把自己的 Telegram 綁定起來收提醒，並能自己開關通知通道。**

---

## 現況與缺口

上線時只有**站內通知**（打開網站才看得到）。要讓提醒主動推到使用者手機的 Telegram，就需要「綁定流程」——把某個 Telegram 對話跟某個帳號對起來。V0.5 的 Telegram 是盡力亂送、沒辦法認人，所以要補。

---

## P3 做的事（白話）

**1. Telegram 機器人**
使用者對機器人輸入 `/start` 會請他去網站拿綁定碼；輸入 `/bind 綁定碼` 完成綁定。其他亂打都回「請到網站操作」。

**2. 綁定碼**
網站產生一組短效綁定碼（10 分鐘、只能用一次、產新的就讓舊的失效），輸錯太多次會被限流。

**3. 一對一綁定**
一個帳號只能綁一個 Telegram、一個 Telegram 只能綁一個帳號。要換要先解除舊的。別人已綁走的對話會被拒絕，請他聯絡管理員。綁定/解除都留紀錄。

**4. 通知通道開關**
使用者可以自己決定要不要收 Telegram。站內通知**強制開啟不能關**（保底）；派送時以「**當下**設定」為準——剛關掉 Telegram，後面就不送了。

## 對齊 domain-spec 的範圍

| P3 做的事 | 對齊 spec 出處 |
|---|---|
| Telegram bot `/start`、`/bind` | **§7** lines 367–372 |
| 綁定流程 + bind code 規則（10min/一次性/產新失舊） | **§7** lines 374–396 |
| 一對一綁定、解除寫 audit | **§7** lines 392–396 |
| 通知通道設定（in_app 必開、telegram 可選、以觸發當下為準） | **§12** lines 603–611 |

**一句話**：P3 切自 spec **§7（Telegram 綁定）+ §12（通知通道設定）**。

---

## P3 的邊界

| 不做 | 交給 |
|---|---|
| 通知怎麼送（送達/重試機制） | **P2** |
| 從 Telegram 建立提醒 | V1 不支援 |
| 靜音標的 / 勿擾時間 / 每日摘要 | V1 不做 |

---

## 做完 P3 之後

使用者能把提醒推到自己的 Telegram，並自由開關通道。
